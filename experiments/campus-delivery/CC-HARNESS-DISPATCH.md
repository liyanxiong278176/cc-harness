# cc-harness 总调度任务：单体生产级校园外卖系统

你是本项目唯一的主编程 Agent。请在当前工作目录中从零交付一个无需上线、但按生产代码标准实现的单体校园外卖系统，并完整记录可审计的 Agent 全链路观测。不得修改当前目录以外的项目文件。

## 目标与技术栈

实现用户、商家、订单、模拟支付、模拟配送、评价、站内通知七个业务域。必须覆盖：注册登录、个人信息、地址 CRUD、优惠券；商家和菜品分类/SKU/库存/营业状态；购物车、结算、库存扣减、订单状态流转、退款申请；支付回调幂等；骑手接单和配送状态；完成订单评价和商家评分；订单通知。

使用经典单体分层（Controller → Service → DAO → MQ → Common），边界清晰、低耦合。后端 Java 17 + Spring Boot 3.x + MyBatis-Plus；MySQL 8；Redis 7；RabbitMQ；前端 React + Ant Design，同一前端区分用户端和商家管理端路由。提供 Maven 多模块（或结构等价且可维护的单体模块）和一键本地启动脚本。

支付、短信、配送等外部能力使用可替换的模拟适配器，不依赖真实第三方服务。

## 生产级红线

- 所有接口有参数校验、统一响应、全局异常和规范错误码。
- SQL 使用参数化访问，敏感字段加密/脱敏，JWT 鉴权和接口权限完整。
- 明确缓存一致性、库存扣减和防超卖策略。
- 消息消费幂等、重试和死信处理可验证。
- 事务边界、操作日志、审计字段和并发处理清晰。
- 提供单元测试、核心接口集成测试、前端关键交互测试。
- Docker Compose 能启动 MySQL/Redis/RabbitMQ/应用；健康检查、迁移、种子数据和故障排查文档齐全。
- 完成前运行构建、静态检查、测试和健康检查；不得仅依据口头声称完成。

## 主 Agent 与 Subagent 规则

你是唯一决策和汇总者。根据当前任务动态派生和销毁子代理，不使用固定角色清单；可按需派生架构、后端、前端、测试、审查、问题排查等子代理。子代理之间暂不直接通信，全部由主 Agent 中转；每次派生都传递最小必要的脱敏上下文和明确文件边界，结果由主 Agent 校验后再合并。发现冲突、失败或重复时记录并处理，不默认为成功。

运行时的 `/workspace` 就是本任务目标目录；直接在此目录创建和修改项目文件，不要再创建名为 `campus-delivery` 的嵌套目录。

## 五阶段流程与交付物

1. 架构与技术规约：架构图、ER/表设计、API 与错误码、代码规范、决策记录。
2. 核心模块开发：后端、前端、数据库迁移、消息和模拟外部适配器。
3. 测试与修复：单元/集成/前端测试，安全和依赖审查，修复后回归。
4. 构建与运行验证：Compose、一键脚本、健康检查、核心业务链路验证和运行手册。
5. 全链路总结：生成《cc-harness Agent开发全链路观测分析报告》，区分已验证事实、未覆盖项和风险。

每阶段必须先完成可验证交付，再进入下一阶段；每个阶段结束输出阶段结果和观测报告。技术决策、失败原因和修复同步写入项目内的决策/记忆记录。
