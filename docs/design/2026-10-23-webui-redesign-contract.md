# cc-harness WebUI 重设计实施契约

## 产品方向

以本机 DeepSeek Harness 为整体信息架构与任务执行展示的交互基线，替代此前以 Claude Desktop 为主的方向。使用 cc-harness 自有品牌与视觉设计。参考边界见 ADR-0118，实测覆盖与限制见同目录的 DeepSeek Harness 观察记录。

目标是适合持续编码工作的成熟界面：层级清楚、行为可预期、文字清晰、细节一致。通过排版、比例、留白和表面层级建立质感。

## 已确认设计

- 视觉：默认中性石墨灰深色，克制的蓝色操作强调；浅色主题具有同等完成度。避免大面积渐变、发光、厚重阴影和过量卡片。
- 布局：左侧可收起的项目/会话树；中间以对话为主，顶部切换对话/轨迹；右侧文件、变更及运行详情按需打开。
- 执行过程：简短进展与紧凑工具摘要持续可见，命令、参数和长输出按需展开；完成后收拢过程，失败和待审批项保持醒目，最终答复独立可读。
- 轨迹：按轮次组织模型回复、工具调用、耗时、结果与错误，支持搜索、展开与关联文件查看；原始参数和技术事件进入详情。
- 长任务：真实计划以可收起的步骤清单呈现，区分已完成、进行中和待执行。无计划时显示当前动作与耗时。
- 2026-10-24 后续调整：输入框上方入口改为“任务列表”，展开后只显示任务名称、状态与已完成数量；持续接收任务事件，打开期间实时更新，并提示连接重连或滞后状态。
- 文件变更：对话内展示本次任务的文件变更摘要，点击在右侧查看具体增删；文件内容预览也位于右侧。补齐可靠差异所需的数据支持属于本轮范围。
- 新指令：运行中普通发送默认排队，显示待执行，支持生效前修改或撤回；独立提供停止并转向，当前动作安全结束后处理新指令。
- 审批与失败：在主对话中就地处理，显示动作、原因与有效操作；允许/拒绝范围准确，错误详情可展开，重试/继续以实际能力为准。
- 覆盖范围：新会话、对话、轨迹、项目/会话管理、文件与差异、模型/权限设置、上下文/记忆/安全详情及各页面状态全面统一。

## 实施约束

服务端任务、工具、审批和事件事实是展示依据。保留当前产品能力与运行语义，逐项核验排队编辑/撤回、停止并转向和差异证据的现有支持，补齐缺口后提供真实操作。

任务文件差异与项目历史产物当前文件预览分别呈现。任务差异必须有前后证据和明确归属；不能把用户原有修改或整个工作区 Git 差异统称为模型修改。旧任务缺少证据时明确显示不可用，不伪造差异。具体证据采集及存储方案需在代码调查后形成实现方案。

运行状态、计划和用量均来自真实数据，缺失值显示未知；阶段位置不换算成任务完成百分比。不展示隐藏思维链。审批拒绝、停止、失败和完成具有不同语义。

运行中保留用户阅读位置，输入与查看详情保持可用；界面应支持键盘操作、清晰焦点与窄屏使用。具体样式令牌、布局比例和断点由实现阶段按本契约设计。

## 验收依据

1. 所有范围内页面使用统一的颜色、文字、间距、控件和状态表达，深浅主题均可读。
2. 真实任务从提交、生成、工具调用到完成的过程连续可见；长输出展开和过程收起不隐藏最终回复、异常或待决事项。
3. 审批允许/拒绝、运行中新消息排队与修改/撤回、停止并转向均验证服务端结果，不仅验证按钮外观。
4. 新建、修改、删除文件的差异与任务归属可核验；覆盖任务前已有用户修改、缺少差异证据、二进制或不可预览文件的真实提示。
5. 切换会话、刷新、断连重连、失败及恢复不丢失已确认状态，不重复执行动作；空态与加载状态有明确说明。
6. 通过适合改动的构建与回归检查，并以浏览器实际操作验证主流程、主题与窄屏；留存可审阅截图和结果。
