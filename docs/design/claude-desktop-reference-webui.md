# Claude Desktop 参考式 WebUI 重设计契约

状态：已确认（2026-09-30）

本文记录 cc-harness WebUI 重设计的范围和交互契约。它取代 [`webui-ux-contract.md`](webui-ux-contract.md) 中旧的三栏/DeepSeek 方向，不改变 Durable Runtime、权限、事件、会话或现有 REST/SSE 语义。

## 目标与边界

- 以本机 Claude Desktop 实机观察到的桌面布局、视觉层级、控件密度和对话反馈作为设计参照。
- 用 cc-harness 自有 React/Vite 页面重做 `web/src`，不导入或依赖 `vendor/deepseek-ui/` 快照。快照目录的归档/清理不属于本次已提交交付范围。
- 保留 cc-harness 名称、项目本地运行模型和全部现有 WebUI 能力；不引入 Claude 账户、云端服务、Claude 模型接入或原生桌面壳。
- 既有 `/api`、SSE、Durable Runtime 与 TUI/headless/SDK 使用的契约继续不变。后端仅增加产物查询与当前文件预览所需的只读 API。

## Claude Desktop 观察记录

本机 Claude Desktop 的新对话页显示：左侧为稳定导航与聊天历史，主区域留白充足并突出对话，导航包含 New、Projects、Artifacts、Customize 等入口；新对话的 composer 位于主区域中下部，对话过程中输入区固定在消息区底部。控件简洁、层级清楚，深色表面和细分隔线较克制。观察使用空白新对话，不发送任何消息。

仅复用上述布局和操作节奏。实现使用 cc-harness 自有文案、图标与素材，不复制 Claude 的品牌资源、源码或账户功能。

## 页面结构与 cc-harness 映射

### 左侧导航与历史

- 品牌区使用 cc-harness 自有标识；侧栏可收起为窄导航轨道。
- 顶部操作映射为“新建”“项目”“产物”“自定义”：新建会话、打开现有本机项目选择流程、浏览当前项目产物、打开现有设置。
- 下方“对话和任务”区域提供会话搜索与历史列表。列表标题、状态和项目归属来自现有服务端投影，继续支持当前已有的跨项目会话浏览和选择行为。
- “产物”只展示当前选中项目；没有选中项目时说明如何选择项目，不展示其他项目内容。

### 对话主区域

- 新会话使用 Claude Desktop 式的居中欢迎区、主 composer 和轻量建议入口；已有会话以对话内容为主，顶部保留会话标题和必要操作。
- 对话区单独滚动，运行中的 composer 固定在底部。新消息到达时保留用户的阅读位置，并提供跳至最新消息的入口。
- 用户消息、逐段流式回复、可折叠工具过程、待审批操作、错误/恢复提示和最终回答继续由现有事件投影驱动。最终回答不被过程折叠隐藏；不显示隐藏思维链或原始协议 JSON。
- 保留当前键盘语义（Enter 发送、Shift+Enter 换行）、斜杠命令、项目目录选择、权限策略、模型入口、运行中排队、停止并转向及继续操作。

### Runtime 详情

- 常态不显示固定右栏。用户从会话标题区或运行状态入口打开覆盖式运行详情面板；面板展示当前已有的 Runtime 状态、事件时间线、审批、上下文/记忆/安全详情和诊断信息。
- 面板只读，支持关闭按钮与 Escape；关闭后保留原对话位置与滚动状态。状态值继续来自 cc-harness 服务端投影，无证据时显示未知。

### 产物浏览与只读预览

- 入口只列出当前选中项目中 Agent 在任意历史任务创建或修改过的项目文件。历史任务的路径集合按规范化项目相对路径去重；可以显示关联任务以追溯文件来源。
- 路径事实来自 Durable Runtime 已持久化的工具观察和工作区变更记录，不扫描全项目后把普通文件加入列表，也不列出 Runtime 内部对象存储中的 artifact。
- 选中产物后读取项目工作区中的当前文件内容，不保存历史快照。路径已删除、移动或不能安全预览时显示不可用状态，不回退到旧内容。
- 新增只读接口为 `GET /api/artifacts` 与 `GET /api/artifacts/preview?path=...&project_root=...`。列表根目录由服务端当前选中项目确定；预览中的 `project_root` 只作项目切换防护断言，服务端必须校验它与当前选择一致，不能用它选择或打开任意目录。预览只接受项目内相对路径；服务端解析后必须拒绝绝对路径、`..` 越界、符号链接和非普通文件。超大或二进制文件显示类型/大小与不可预览说明，不尝试执行或下载。
- 两个路由只查询历史变更事实和当前文件，不创建/修改文件、不改变 Runtime 状态、不接受任意项目根路径。现有 API 路由和行为保持不变。

## 视觉与响应式规则

- 默认深色主题，沿用现有深浅主题切换能力。色彩、留白、圆角、字体层次和 hover/焦点反馈向实机观察的 Claude 桌面页靠拢；对话正文保持最高视觉权重。
- 采用稳定的左侧导航和宽阔的居中内容区；在窄窗口下收起侧栏为轨道或抽屉，产物预览和运行详情覆盖内容区，不挤出第三个常驻栏。
- 使用单一令牌体系与一致间距，避免多重覆盖样式、霓虹背景和无关装饰。键盘焦点、减少动态效果与可读对比度继续有效。

## 保留的 cc-harness 操作

新 UI 必须继续连接当前已有的项目目录门禁、会话历史/搜索、会话创建和切换、composer 与斜杠命令、模型/提供方设置、三档权限、工具审批允许/拒绝、消息队列、停止/继续、SSE 流式输出与断线对账、能力说明、诊断、主题切换及 Runtime/上下文/记忆/安全详情。页面换壳不能模拟成功状态或成为事实源。

## 文件范围

- 用新的自有实现整体替换 `web/src` 页面源码，并从 `web/vite.config.ts`、入口和 CSS 中移除 DeepSeek 快照别名/import。
- 不新增对 vendor 快照的构建别名或源码依赖；是否清理 vendor 归档应作为单独的仓库维护变更审查。
- 保留现有 `web` 工程、Vite 构建入口、Python WebUI 静态资源托管、`web/package.json` 中仍需要的依赖、服务端 API 和 Runtime。
- 保留 DeepSeek UI 观察报告作为历史记录；它不再是当前设计依据。
- 更新旧 WebUI 设计契约和 ADR-0111 状态，链接至本契约与新 ADR。

## 完成条件

1. 空会话、活动对话和长对话均采用 Claude Desktop 参考的信息层级，输入区与对话滚动位置行为稳定。
2. 现有 cc-harness 项目、会话、队列、审批、停止/恢复、流式、设置和状态详情功能均在新布局中有明确入口且继续走原有 API/Runtime。
3. Runtime 面板按需覆盖打开；默认对话不保留常驻右栏。
4. 产物只来自当前项目的全部历史任务，按路径去重，并且预览只读当前项目文件。
5. 当前 WebUI 无 DeepSeek UI 源码/构建别名依赖；项目中不引入 Claude 产品资源或第二套 Runtime。
