# cc-harness WebUI 体验设计契约

状态：已确认（2026-09-15）

本文记录 cc-harness WebUI 后续重构的共同设计结论。它约束页面呈现和交互语义，不替代 Runtime、事件流、权限、上下文或记忆的事实契约。

## 参考基线

- 视觉基线：Codex 风格的克制编辑器界面——石墨灰表面、低干扰边框、单一蓝色主操作色。
- 工作台结构：DeepSeek Harness 风格的项目/会话树、固定输入区和可收起的右侧运行面板。
- 运行事实：cc-harness Durable Runtime、不可变事件流、checkpoint、权限、上下文、记忆和安全模块是唯一权威来源。
- Agent 流程参考 Claude Code 的“收集上下文 → 执行动作 → 验证结果”循环及分层权限模型：
  [工作流程](https://code.claude.com/docs/en/how-claude-code-works)、[权限模型](https://code.claude.com/docs/en/permissions)。
- DeepSeek 页面结构以已审阅的上游快照和现场记录为准：[`deepseek-harness-ui-observations.md`](../deepseek-harness-ui-observations.md)。

## 信息架构

桌面端固定为三栏：

1. 左栏 256–280px：项目节点、会话历史、搜索和新建会话。
2. 中栏：唯一可滚动的对话区，输入框固定在底部。
3. 右栏约 320px：紧凑 Runtime 状态面板；可收起，窄屏改为抽屉。

普通状态不使用遮挡式弹窗。审批、错误、恢复和不可逆操作使用明确的卡片，并保留可复制的原因和证据。

## 视觉规范

- 默认深色主题，浅色主题复用同一套设计令牌。
- 石墨灰作为基底；蓝色表示主操作/运行中，绿色表示完成，橙色表示等待，红色表示错误或硬拒绝。
- 移除霓虹渐变、发光边框和大面积装饰背景。
- 统一圆角、8px 间距节奏、字号层级和阴影；不得通过多段覆盖式 CSS 改写同一令牌。
- 对话正文优先，工具过程和 Runtime 细节保持低对比度。

## 输入与运行中交互

- 未选择有效项目目录时，输入框可见但发送不可用，并给出可操作提示。
- 空闲时 Enter 发送，Shift+Enter 换行。
- 运行中默认将新消息写入当前会话的持久 FIFO 队列，不打断当前动作。
- 用户需要改变方向时，显式执行“停止并转向”：先保存取消事实和 checkpoint，再把新消息交给主 Agent 重新规划。
- 审批等待期间允许继续输入，消息标记为“审批后发送”，不伪装成永久排队。
- 会话切换立即切换可见内容；旧请求必须取消或丢弃，草稿、光标和滚动位置按会话保存。
- 运行阶段在输入区上方以单个状态圆圈呈现；点击圆圈打开只读的目标契约与执行计划浮层，内容来自 Runtime 投影/不可变事件，缺失时显示未知。

## 模型回复呈现

状态圆圈沿用统一的阶段语义：

`准备上下文 → 流式回复 → 工具调用 → 等待审批 → 验证结果 → 完成/可恢复失败`；阶段文字只在圆圈旁显示，详细目标契约和计划按需点击查看。

- 用户消息立即本地回显，服务端事件到达后幂等对账。
- 模型输出逐段流式显示，并在完成后转换为正式 Markdown。
- 最终回答始终独立显示，不进入“思考中”折叠区。
- 已完成轮次默认只显示阶段摘要；工具名称、范围、结果和错误可以手动展开。
- 不展示隐藏思维链、内部事件 JSON、调度字段或 provider 私有协议；目标契约浮层可以只读展示 Runtime 已确认的 `acceptance_criteria` 与计划 Todo。
- 默认使用简体中文解释计划、进度、结果和错误；代码、命令、路径、堆栈和原始 provider 错误保持原样。

## 异常与恢复体验

- 网络/SSE 短断：自动重连并从最后事件序号补读，显示重连状态。
- 投影或 checkpoint 不一致：暂停新动作，校验不可变事件流，重建投影后从最近完整 checkpoint 继续。
- 工具失败或用户拒绝：只结束当前工具动作，将真实结果交回 Agent，允许继续或重规划。
- 用户停止：保留已落盘事件、部分流和取消原因；会话仍可发送后续指令。
- 租约冲突：进入只读/恢复中状态并说明持有者，不返回无解释的 500。
- 安全硬拒绝或不可恢复错误：停止运行并展示原因、事件序号和可行下一步。

## 上下文、记忆与安全

- 底部只显示模型、上下文占用摘要和当前权限策略。
- 右侧详情展示真实 token 分类、压缩/卸载、记忆检索层级与命中、安全决策和更新时间。
- 每个 Run 初始只注入 L3；确有需要时按 L3 → L2 → L1 → L0 检索，并展示可审计轨迹。
- 没有 Runtime 证据时显示“暂无数据”或“未知”，不显示静态估算百分比。

## 流畅性与可访问性目标

- 关键点击在 100ms 内有视觉反馈。
- SSE 更新只刷新受影响的会话、消息和状态卡，不触发整页重渲染。
- 长对话采用虚拟化或分段渲染；会话列表刷新不得阻塞对话区。
- 保持焦点、键盘导航、`aria-live` 状态播报和减少动态效果模式。
- 发送、审批、停止、恢复、错误和切换会话均有可观测的加载/禁用/完成状态。

## 验收门

必须使用真实外部模型，并同时通过：

- 新建项目/会话、多轮对话、流式输出和最终答案展示。
- 工具允许、工具拒绝后继续、运行中排队和停止并转向。
- 刷新、SSE 断线、进程中断、checkpoint 续跑和投影重建。
- 工具成功但状态/结果延迟落盘时的幂等对账与重复调用防护。
- 会话切换、删除、草稿保留、长对话滚动和窄屏抽屉。
- 上下文压缩、卸载、分层记忆、安全策略和权限状态的实时展示。
- 深浅色主题、键盘操作、视觉回归截图、无原始协议气泡和无密钥泄露。

## 非目标

本契约不引入第二套 Agent Runtime，不让浏览器成为事实源，不把 DeepSeek 品牌素材当作 cc-harness 品牌，不以静态截图或 mock 成功替代真实 Runtime 验收。

## 当前实现映射

- `web/src/cc/app.tsx`：三栏工作台、会话级草稿、流式消息、状态圆圈与目标契约/PlanGraph/Todo 浮层、持久后续消息队列、审批后发送、停止并转向、上下文/能力详情。
- `web/src/styles.css`：单一石墨灰/浅色令牌、低干扰编辑器表面、窄屏布局、长对话 `content-visibility` 优化和减少动态效果支持。
- `cc_harness/webui.py`：审批等待期间仍允许 `FollowUpQueued`，由 Durable Runtime 的前置门控保证审批决定前不启动后续 Run。
