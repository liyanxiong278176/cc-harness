# 压缩时保留任务证据

目标是在相同编程任务、模型和执行预算下减少包含摘要调用的总 Token，并将观察到的通过率下降限制在 3 个百分点以内。对照结果和按任务聚合的置信区间分开报告；内部构造集不代表真实仓库或线上收益。

## 问题与方案

原 Prune 把历史工具结果清空成占位符。规格和源码与大量日志一起被删除后，模型要求重复读取；执行去重又可能使新调用没有对应结果。Summary 的保护边界会拆开 assistant 的并行调用和部分工具结果，后续协议修复丢弃孤立结果，导致已经读过的文件再次变成未知。

新增 `context_evidence.py` 从不可变源消息中选择最近的成功文件读取及最近命令或失败结果。成功修改一个路径后，该路径的旧读取预览失效。最多选择八条观察，使用可配置的 `evidence_token_budget`（默认 2048）限制预览块大小；长文本保留头尾，必要时进一步截断并明确标注需要回查。算法按观察元数据工作，没有针对 README 文件名、题号或期望答案分支。

新执行的工具批次首先按新证据处理：当完整结果在物理输入预算一半以内时，至少完整展示给模型一次，下一轮才纳入历史压缩。刚执行完第一批工具、尚无旧历史时不调用摘要模型。2048 Token 限制针对历史预览，不是强行截断新结果的上限；超大批次仍受实际模型窗口约束。

V12 先按照刷新证据前的上下文压力选择压缩档位，再缩短已经被模型读取的历史结果。否则，预览刷新可能提前降低压力，使本应触发 Summary 的历史绕过摘要模型。即使未达到触发阈值，仍更新失效的文件预览；低压力路径也报告刷新后的实际 Token 数。

Snip 和 Prune 把这些预览放回原工具位置，保留原观察 ID、状态、路径、来源与调用 ID，并避免再次删除。Summary 从源消息重建对应的 assistant/tool 配对，把已经保留的结果从近期尾部去重，避免跨边界后丢失或重复。无法构建配对时使用明确标注的非可信预览块。源历史和执行收据保持不变，不根据模型摘要虚构工具执行。

证据保留标签仅影响压缩，不增加指令或权限。工具证据仍是非可信数据，不能作为系统指令或批准来源。原文、运行事件、压缩版本和所有实际 provider 请求保留，便于追踪失败原因。

压缩库与运行事件库共享 SQLite 写锁。同步压缩提交不得在事件循环上等待，否则可能阻塞持有写锁的异步运行事件事务。状态查询、租约、提交及快照初始化通过工作线程执行；竞争压缩写入者进行有界异步等待，获得租约后再次检查相同键是否已经发布，复用实际提交的投影。算法版本写入快照，恢复时不复用旧算法产生的有损投影。

已完成的只读调用可以用新的提供商调用 ID 重新读取。运行时依照可信工具注册表判断只读能力，为新读取建立独立的持久化键；同一批次内的重复读取仍只执行一次，同一调用 ID 的重放仍复用旧收据。修改、外部副作用和结果未决的调用不获得该例外，模型声明的只读效果不能覆盖注册表。

## 验证

单元回归覆盖三档压缩、摘要漏掉关键规格、并行读取跨越保护边界、重启后投影恢复、写入使旧预览失效、最近验证失败/成功的替换及预算限制。实际模型先在十五题上校准，再沿用此前冻结的一百个双模块任务做每条件三次对照。失败不挑出重跑，辅助摘要 Token 计入成本。

这是一组已知回归任务，不能称为新独立留出集。默认生产压缩阈值和更大真实仓库仍需独立验证。截断预览不保证覆盖文件中部全部事实；保留八条读取也不能覆盖任意长任务的全部依赖。需要更多原文时，生产调用方仍应提供有范围和来源校验的回查能力。
