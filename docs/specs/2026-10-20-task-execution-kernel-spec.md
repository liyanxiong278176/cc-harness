# 任务执行与编排内核改造规格

日期：2026-10-20。状态：用户已整体批准，代码改造与确定性验证已完成；真实服务联调边界见验收报告。

需求来源：用户提供的《第 4 章 任务：编排、长程推进与协作流转》，以及同日设计访谈中的 12 项已确认决定。

## 1. 范围与权威对象

改造现有 Runtime / Loop 的任务执行、规划、委派、等待、恢复和验证流程。以现有 Run 为任务身份，沿用事件、投影、对象证据与单写者机制，不另建竞争的任务状态来源。

上下文构建、压缩、卸载、检索、MCP、记忆及既有权限安全机制保持原行为，通过现有能力接入点使用；不换框架，不引入示例中的 AgentScope、Qoder 或云端服务。界面只同步必需的状态、控制与输入行为，本次不重新设计界面。

## 2. 已确认的使用行为

1. 支持多维预算，未配置维度无限；子任务消耗计入父任务总额。
2. 采用 CREATED、RUNNING、WAITING_INPUT、WAITING_APPROVAL、WAITING_EVENT、PAUSED、VERIFYING、COMPLETED、FAILED、CANCELLED；排队与租约单独记录。
3. 暂停后恢复原 Run；取消为终态，取消后继续建立关联的新 Run，复用成果前核验。
4. 普通任务默认自主推进；明确要求先出方案或规则要求审批时，计划批准前只读探索。
5. 按收益自主委派，主 Agent 仍负责整合和验收，子 Agent 不扩大权限或预算。
6. 执行中的补充、纠正及时进入当前任务；进度询问及时答复。
7. 关页面后台继续，关终端自动暂停相关任务。
8. 验证失败后在授权和预算内自主修复，遇到决策缺口、边界或持续无进展时停止自主推进。
9. 要求变化时，受影响子任务在安全边界停下，更新契约后继续；无关任务照常运行。
10. 崩溃或电脑重启后恢复记录，保持暂停，等待用户说“继续”。
11. 新内核能接续旧任务；转换不确定之处暂停说明，保留旧证据。
12. 预算耗尽进入暂停，保存进度与未完成事项；增加额度后继续原 Run。

## 3. 建议的内核结构

以下为配合已确认行为的实施方案，随本规格整体确认。

- Prepare：读取权威状态、目标版本、当前计划与待处理事件，通过原 Context Builder 装配输入。
- Model：把输出解释为行动、委派、询问、等待、计划变更或完成申请；模型不能直接提交完成状态。
- Act：统一经过动作契约、权限、审批、预算、资源隔离和执行接入点；不绕过现有工具运行链。
- Observe：先提交结构化观察和产物引用，再供后续模型使用；工具、用户、子任务与外部事件使用可追溯来源。
- Verify：选择与目标及风险匹配的验证器，返回通过、结构化缺口及可修复性；失败反馈进入修复或重规划。

Middleware 在任务创建、Prepare、Model、Action、状态变化和 Verify 的明确前后边界运行，声明顺序与读写范围，返回结构化 Decision / Patch，由内核校验和统一提交。禁止扩展直接另存权威状态或绕过 Action 接入点；扩展失败不得静默放开权限或验收门禁。

## 4. 状态、计划与完成

任务投影包含目标及其版本、阶段、计划与 Todo、已确认事实、阻塞原因、子任务、产物、预算、等待条件与完成证据。消息历史是事实记录之一，不替代权威任务状态。

沿用 PlanGraph 及 Todo 投影：简单任务使用轻量计划，复杂任务表达阶段、依赖、输出和验收门禁；不为每次工具调用生成 Todo。重规划保留已完成事实，记录触发原因和目标变更，禁止改写历史或降低验收标准掩盖失败。

显式 Plan Mode 将计划提交与计划批准分开；批准绑定计划版本与范围，范围扩大后按权限规则重新判定。阶段验证通过后才推进有依赖节点。

模型可以申请完成，Runtime 也可沿用 ADR 0105 在证据满足时发起验证，不要求模型输出特定完成标记。只有当前目标要求的证据全部满足、必需子任务已验收且无未解决的审批或结果不明动作，才进入 COMPLETED。目标只要求形成待审批成果时，未发布不构成失败。

## 5. 委派与控制权交接

子任务契约包含目标、边界、已知事实与引用、能力权限、预算、输出结构、失败策略、验收条件及输入版本。复用现有子任务上下文装配，默认不复制父任务全部历史或权限。

子任务结果作为 Observation，经过结构、版本和父任务验收后采用。读任务可并行，写任务沿用隔离工作区与资源冲突约束；评审绑定固定变更版本和测试证据。按关键性与错误类别选择停止依赖路径、保留部分成果、有限重试/重派或升级给用户，不一律终止所有无关任务。

Delegation 保留父任务责任；Handoff 必须持久记录接收者、责任转移、目标状态和继续点。无合法接收者时等待用户，不通过一条自然语言消息假装交接完成。

## 6. 等待、暂停与恢复

等待输入、审批或事件时保存原因、关联对象、事件游标、超时策略和继续点，释放 Worker；匹配事件到达后可恢复等待任务，但不能覆盖显式暂停。事件重复、迟到或顺序变化不得重复执行动作。

暂停与取消先停止新派发，在安全边界处理在途操作；无法确认副作用结果时保留 Outcome Unknown 并先对账。父任务暂停时相关子任务一并停止自主推进，取消沿父子关系传播，已发生副作用保留事实。

Continuation 使用现有状态、计划、事实、失败尝试、产物、等待项、预算与权限引用重建输入，不改动现有压缩和记忆机制。

关终端暂停须覆盖终端正常退出与强制关闭，采用 Runtime 侧可观察的终端归属和存活机制，不能只依赖退出回调。仅暂停该终端负责的任务，不影响其他会话；多个终端连接同一任务时的归属规则需要在实现前明确并纳入契约测试。

## 7. 预算和可靠性建议

步骤、运行时长、Token、费用、工具调用、并发与风险动作分别计量；费用估算与供应商实测分开标识。子任务分配额度时同时检查父任务剩余量，并行派发需要预留以避免重复花费同一余额。

用户已确认预算耗尽进入 PAUSED 并附 budget_exhausted、剩余交付和已用额度，等用户调整后恢复，不标为完成；这是可恢复停止语义，对参考章节中预算耗尽产生终态的要求作显式调整。接近上限时停止不必要的委派并收敛；已开始调用如实收尾，不能承诺外部计费绝不超出预估。

瞬时错误有限退避，参数错误修正，权限拒绝等待或停止，环境缺失修复，重复失败触发重规划。重试副作用前核对上次是否执行，不假定超时即未发生。无进展检测沿用有效事实变化，不能用调用次数或文本增长冒充进展；阈值应配置化，不设置未经确认的固定任务总限额。

## 8. 迁移与实施顺序

1. 固化新领域模型、合法迁移与事件 schema，划清业务状态和调度状态。
2. 调整现有 Worker / Kernel 的五阶段流程与扩展提交边界，保留能力接入。
3. 接通预算、计划审批、即时用户反馈、子任务契约更新和验证修复。
4. 接通等待唤醒、暂停取消、终端归属与异常恢复。
5. 实现静止安全点迁移、事件兼容及客户端行为同步。

迁移前验证事件与证据完整性，不改写旧事件；保持 Run 及关联任务身份，提交带版本与原因的迁移事实。新旧 Worker 不得同时写同一 Run；取消任务不复活，旧未完成任务迁移后保持暂停。不确定状态不猜测，保留证据并说明缺口。旧数据、失败迁移记录和可回退来源均保留。

历史规格作为旧版本依据保留；新规格批准后明确其替代范围。现有未提交修改必须保留并据实际内容整合，不能覆盖其他工作。

## 9. 验收要求

- 合法状态迁移、非法事件拒绝、等待原因区分、暂停和取消的父子传播。
- 扩展顺序、Patch 冲突和短路规则，确保扩展不能绕过权限或提交完成。
- 计划批准前禁止目标工作区写入；重规划不丢历史成果，过期计划批准不扩权。
- 用户纠正及时生效，受影响子任务更新，旧版本结果不错误验收。
- 断开页面继续、关闭终端暂停、异常重启等待继续，且不误伤无关会话。
- 在动作已提交但结果未返回等安全边界注入中断，恢复先查询原动作，副作用不盲目重放。
- 父子预算聚合、并发预留、耗尽后不再派发、恢复不清零；未配置维度无隐式上限。
- 完成由目标相关证据决定，验证失败进入修复，无进展停止，取消后新 Run 仍可核验复用成果。
- 旧任务迁移可重复执行且不重复导入，坏证据拒绝，迁移前后权威任务关系一致。
- 上下文压缩、卸载检索、记忆读写、MCP 和现有权限链继续进入真实执行路径；以针对性回归证明，不以源码仍存在代替。

测试先覆盖确定性契约并使用固定模型输出；真实 Provider/MCP 的必要联调与模型评测分开报告，不以模拟测试冒充端到端验收。
