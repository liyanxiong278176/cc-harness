# ADR-0119：采用 Langfuse 承载 Agent 可观测性与评测界面

状态：Accepted；日期：2026-10-25，实施记录更新于 2026-10-26。用户已确认整体设计并授权实施；部署、代码和确定性验证已落地，真实模型验收因服务 HTTP 402 尚未完成。见[运行手册与验收记录](../observability-langfuse.md)。

本轮将虚假完成、执行阻塞与上下文失效全部纳入观测与评测闭环，明确采用 Langfuse 承载项目内跨历史任务的问题总览、分类筛选、轨迹详情及评测操作。用户选择以 Langfuse 为日常排查界面，并明确要求 cc-harness 页面保持现状，因此不在本轮增加本地诊断页面、摘要、跳转控件或其他前端改动，集中使用 Langfuse 的观测与评测界面。

问题按既有九个能力域与具体问题两层组织，同一轨迹允许多个问题标注，每项标注关联步骤、依据及确认状态；检查覆盖与成功任务分层抽查的已确认术语见根目录 `CONTEXT.md`。沿用 ADR-0020 的既有边界：本地 Runtime 事件和统一评估证据核心仍分别保存执行与发布事实，Langfuse 接入不将其替换为第二套 Runtime 或发布事实源。

部署采用当前 Windows 电脑上的 Docker Compose 自托管，不使用官方云版。用户明确要求数据保存在 D 盘而非 C 盘；数据库、对象存储、队列持久化、持久日志及备份均须实际落在 D 盘，不能仅将 Compose 配置文件放在 D 盘而让数据继续写入 C 盘的 Docker 数据盘。实施时需核验各服务挂载与 Docker 数据盘的实际位置，再用持久化读写及重启检查验证落盘结果。

2026-10-25 的接入前检查发现 Docker 数据盘位于 C 盘。实施后，活动数据盘为 `D:\DockerDesktop\local-appdata\Docker\wsl\disk\docker_data.vhdx`；启动与存储验证脚本会核对活动 Docker backend 的数据目录，原 C 盘文件保留为迁移前副本。Langfuse 已部署，完整冷备份及临时卷恢复抽检通过。

模型辅助分析复用 cc-harness 当前配置的模型服务，每次使用独立分析请求，只读取选定轨迹，不继承被分析 Agent 的记忆，不执行工具；本轮不要求另行配置评审模型。Langfuse 的本机自托管不改变该模型服务原有的执行位置。

分析内容采用脱敏后的完整可见轨迹，包含全部用户消息、模型可见回复、工具调用参数及结果，不将摘要加异常片段作为默认替代。该选择授权方案中的自动分析按此范围复用当前模型服务，不要求每条已选中轨迹重新确认相同的传输范围；沿用既有不暴露凭据、不以隐藏思维链作为评测依据的边界。长轨迹需采用保留完整覆盖范围的分段处理，不能以静默截断冒充全量检查；未完成的检查仍按实际覆盖标记。

Langfuse 或分析模型暂不可用时，主任务继续执行，轨迹及待补工作先保存在本地，服务恢复后自动补传、补分析；检查完成前保留真实的未完成检查状态，不将诊断服务故障改写为任务失败或检查通过。该容错边界仅针对观测同步与辅助分析，既有 Runtime 本地事实写入、完成验证及安全约束继续生效。

本轮同时接通自动回归与发布门禁：经确认的真实问题沉淀为可复现的评测用例；修改提示词、模型或工具逻辑后自动回归，关键用例失败时拦住发布，结果在 Langfuse 查看。用例从真实失败到开发集、修复稳定后进入冻结回归集的生命周期，沿用既有真实失败评估闭环；模型分析产生的待核实线索不自动成为标准答案。

主任务执行与发布判定是不同边界：观测服务故障不打断日常主任务，并不意味着发布门禁可以在缺少必要评测证据时放行。

发布门禁使用可核验的结果：冻结的关键回归用例查出测试失败、必需产物缺失、越权操作等确定错误时阻断发布；必要评测未完成或证据缺失时暂不放行，补齐后重新判定。模型提出的待核实问题仅提示人工复核，不单独阻断发布。

自动回归在当前开发电脑执行，沿用本机开发与测试环境，结果写入同机自托管的 Langfuse；本轮不以远端 CI 机器为执行前提。

回归采用分层触发：提交代码前运行不调用模型的快速检查；推送或发布前运行完整回归，包含固定任务的 Agent 执行与验收。完整回归保护已确认的关键场景，公开 benchmark 继续作为独立评测，不加入每次提交的高频检查。检查结果须绑定实际被检查的代码、配置与任务版本，后续变更不能沿用旧结果宣称通过。

完整轨迹采用长期保留，默认不按时间自动删除；后续根据 D 盘实际占用另行调整保留策略。该选择覆盖普通成功、失败及评测轨迹，不因任务成功就自动清理原始执行证据。

本轮只接入集成启用后开始的新任务，不导入、回填或自动分析接入前的历史任务。项目内跨任务总览覆盖接入后的历史积累，不据此扩张为旧任务迁移；正式回归用例可复用现有冻结用例，但不要求导入其过往运行轨迹。

辅助模型分析不设置每日用量上限，按照已确定的异常全分析、成功分层抽查规则持续处理。该选择不等于无限并发或无限重试；仍使用可配置的工作并发和有限错误重试，服务失败时保留待补工作，不影响主任务。

Langfuse 数据映射、同步实现、回归闭环、验收要求及可调实施初值见[完整设计](../design/2026-10-25-langfuse-observability-evaluation.md)。词汇表只保留领域定义，部署与运行策略以本 ADR 和完整设计为准。

评测集是本轮明确交付项。用户已确认首版 30 条 Agent Golden Set 候选加 12 条流程保留任务；2026-10-26 最新指令明确只执行这 42 条 Agent 任务，取消仓库 pytest 执行、提交快检及其门禁依赖。[首版评测集设计](../design/2026-10-25-langfuse-evaluation-dataset.md)给出具体用例目录、环境与独立验收契约、Langfuse Dataset/Experiment 关联及保留集边界。实际夹具、验证器、运行命令和试跑结果必须一并交付，未完成真实验收前不记为已冻结基线。
