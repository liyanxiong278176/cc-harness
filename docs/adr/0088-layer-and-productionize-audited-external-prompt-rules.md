# Layer and productionize audited external prompt rules

Replace the monolithic prompt composition with a stable core, structured runtime contract, on-demand capability modules, and runtime model-capability adapters. All target models share the same vendor-neutral production prompt by default. The initial adapter scope is DeepSeek, GLM, Kimi, MiniMax, and Qwen; Claude and GPT have no dedicated adapter or prompt branch. Effective rules from license-compatible official and open-source Codex, OpenHands, SWE-agent, and Anthropic materials are source-mapped, adapted, lightly validated, and then enabled in production rather than remaining comparison fixtures; complete proprietary or unofficially extracted Claude Code prompts are not copied verbatim. Lightweight validation covers prompt generation, target-model tool-use smoke tests, core coding flows, severe security regression checks, Token anomaly checks, and immediate rollback to the prior stable prompt; full benchmark suites are not a release prerequisite.

External rules are fetched only during an explicit research or upgrade workflow, reviewed, and recorded with a stable source URL, review date, license record, content digest, and local rule version. A release may additionally pin an upstream commit when the source snapshot is vendored; the current registry deliberately stores only adapted local rules, not upstream prompt text. Production agents never fetch or update prompts from the network at runtime. Prompt content is also confidential at the product boundary: the TUI, ordinary diagnostics, telemetry, logs, and exports may expose only operational metadata such as version, irreversible digest, layer token counts, cache epoch, capability state, and compression metrics, never effective prompt text or reconstructable rule/source mappings.
