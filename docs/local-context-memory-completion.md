# 本地上下文与记忆能力补齐：设计访谈

本次补齐面向单用户、本地编码 Agent，覆盖已讨论的必要能力与轻量实现；不建设多租户、企业知识平台、远程 Skill Registry 或分布式状态服务。本文记录访谈决策，尚不是已完成实现的声明。

## 已确认决策

### 1. 遗忘与历史清除分离

用户选择方案 A：遗忘清除目标长期记忆及其派生内容，包括向量、场景、画像和注入快照，并阻止从原来源再次提取；保留原始聊天和执行证据。原始历史清除属于独立操作。

该决策沿用 CONTEXT.md 中的“级联遗忘”“本地数据生命周期”以及 ADR 0023，不另建重复术语或 ADR。后续实现必须验证派生内容失效和后台再次提取的边界，不能仅以墓碑标记或删除向量宣称完成。

### 2. WebUI 与命令入口同时提供

用户选择方案 A：记忆查看与遗忘、Skill 启停、上下文来源查看同时提供 WebUI 和命令入口。两种入口复用同一套后端服务与状态，WebUI 提供基本管理，命令入口支持调试与脚本操作。

### 3. 上下文完整性失败时先重建再暂停

用户选择方案 A：压缩或恢复后的完整性检查发现目标、约束、未解决错误或证据引用缺失时，从原始事件和权威状态自动补回并重新检查。若仍不完整或无法满足窗口预算，暂停并展示具体原因；不得重新执行历史工具动作来重建上下文。

### 4. 有明确来源的长期事实自动保存

用户选择方案 A：用户明确表达的稳定偏好，以及经工具验证且具有后续价值的项目事实，可以自动进入长期记忆，并保留来源和验证时间。模型推测仅保留在当前任务中，不自动进入长期记忆。所有长期记忆仍是建议性参考，不替代当前事实、项目规则或审批。

### 5. 本地 Skill 支持项目与用户两级来源

用户选择方案 A：项目专用 Skill 随项目保存，通用 Skill 存放在用户目录。项目 Skill 需明确启用；同名 Skill 不静默覆盖，展示来源并由用户选择。此处明确启用属于产品功能的授权行为，不表示每次读取已启用 Skill 都重复询问用户。

### 6. 项目迁移后的引用恢复限于当前项目

用户选择方案 A：项目移动后优先在当前项目内用相对路径和内容哈希恢复旧引用；不能确认时标记为失效，由用户在 WebUI 或命令入口指定新位置并校验内容，不自动搜索本机其他目录。内容变化不能冒充原始证据恢复成功。

### 7. Skill 更新默认对下一个任务生效

用户选择方案 A：当前任务固定使用已加载的 Skill 版本，重启恢复沿用该版本；更新默认对下一个任务生效。用户可显式重新加载，新旧版本及生效边界必须可追溯。快照覆盖本次加载所依赖的指令和资源，不得仅固定 SKILL.md 而让脚本或模板静默漂移。

## 既有约定

- SQLite 事件仍是 Run 状态的权威来源；续行包和可读交接摘要是可重建视图。
- 项目记忆默认隔离，跨项目共享需显式启用。
- 自动记忆作为建议性参考，不能覆盖当前指令或成为审批依据。

## 已确认的实施方案

用户已确认按以下方案实施。技术细化复用现有约定；验收结果单独记录，不将设计声明当作已通过验证。

### 1. 结构化续行与完整性检查

- 在现有事件、目标契约、工作状态、审批和工具结果之上生成版本化续行视图，包含目标、验收条件、约束、最新纠偏、事实和来源、决定、未解决错误、待办、阻塞、下一步、证据引用、待决动作和恢复所需的权限及预算快照。
- 高风险执行事实从权威状态确定性提取；叙述摘要可由模型生成，但不能代替工具结果、审批或实际验证状态。
- 保留机器可读信息包与人可读交接摘要；两者都是可重建视图，不引入第二个权威状态写入路径。
- 模型调用前检查关键项覆盖、来源版本和引用可用性；完整性失败时有界重建并重新验证，仍失败则暂停。不得因恢复包中的旧权限快照扩大当前权限。
- 区分状态快照与安全执行边界，复用动作恢复契约；结果未知的副作用先核查，不盲目重放。

### 2. Context Policy 与调用来源清单

- 用一份版本化本地配置统一预算、输出和工具预留、压缩阈值、保留项及记忆注入策略。
- 在现有调用 Manifest 上增量记录实际进入模型输入的项目规则来源及哈希、记忆 ID/版本、Skill 快照、证据引用、变换方式和遗漏原因。
- 保持敏感正文与诊断元数据分离，不为本地产品增加企业 ACL 或逐片段权限证明平台。

### 3. 记忆质量和级联遗忘

- 自动写入需有可验证的来源；明确区分用户陈述、工具验证事实、模型推测和当前任务临时状态，推测不自动晋升长期记忆。
- 记忆保留来源、项目范围、验证时间、有效性和版本。跨项目共享维持显式边界，不因本次改动自动扩大召回范围。
- 建立足以覆盖原子、场景、画像和注入快照的派生关系；遗忘即时阻止新的召回和注入，更新或失效关联派生内容，保留最小撤回标识以防原来源再次提取。
- 后台提取、聚合、已缓存快照与遗忘并发时不得重新发布已撤回内容。正在运行的模型无法撤回已接收输入；后续模型调用需使用更新后的视图，不将遗忘表述为原始历史已销毁。
- 同时提供 WebUI 与命令入口进行查看和遗忘；独立说明原始历史清除边界。

### 4. Workspace 与 Artifact

- 在现有目录布局中标明输入、临时文件、权威状态、交付产物和验证证据的职责，不强制迁移全部目录。
- 为产物记录来源、所属任务、摘要和验证状态，不以模型写出文件等同于产物已经验收。
- 自动清理仅覆盖宽限期后的未提交孤儿；可恢复任务、检查点、有效引用和证据仍是保留根。提供可审查的清理预览，沿用现有数据生命周期约定。
- 引用迁移仅在当前项目内恢复，失效时提供手动重新绑定；历史快照和当前文件必须明确区分。

### 5. 本地 Skill

- 支持项目目录与用户目录，发现时仅展示精简描述，选中后按需加载指令与资源。
- 明确启用，处理同名来源冲突；声明所需工具与环境，执行仍经过现有权限和动作路径，读取 Skill 不授予额外执行权限。
- 固定任务使用的指令与依赖资源快照及内容哈希；恢复时验证一致性，显式重载记录新生效版本。
- 提供 WebUI 和命令入口用于查看、启停、冲突选择和重新加载。不建设远程 Registry、企业发布流程或插件商城。

### 6. 两种入口与诊断

- WebUI 提供记忆、Skill、上下文来源和恢复失败原因的基本查看与操作；命令入口暴露同一后端服务，支持脚本和诊断。
- 状态变化与后台任务一致，不在界面中维护独立的记忆、Skill 或续行事实副本。

### 7. 实施顺序

1. 核对现有实现与既有 ADR，列出真实缺口，补续行视图、Policy、Manifest 与完整性检查。
2. 补记忆来源验证、派生关系、撤回传播及后台并发保护。
3. 补引用迁移、产物元数据和可审查清理。
4. 补本地 Skill 的发现、启用、版本快照与按需加载。
5. 接通 WebUI 和命令入口，完成针对性回归与必要的集成验证。

### 8. 验收标准

- 多次压缩后重启，目标、最新纠偏、未解决错误、待决审批与验证证据仍可恢复，且不会重做已完成副作用。
- 人为移除关键上下文时先自动重建，无法恢复时明确暂停；不静默放宽约束。
- 遗忘后原子、派生场景、画像和快照均不再召回该内容，后台工作与重启不能使其复活；原始历史仍按独立规则保留。
- 项目 A 的事实不会默认为项目 B 的长期记忆；模型推测不会因摘要或聚合升级为已验证事实。
- 项目迁移能恢复相同内容的引用，篡改或失效引用可检测；清理不会删除有效恢复根。
- Skill 修改不会改变当前任务已固定版本，重启仍使用一致快照；显式重载可追溯，项目文件不能自行授予执行权限。
- WebUI 与命令入口对同一记忆、Skill 和调用来源显示一致事实。
- 运行相关单元、并发和恢复集成测试，并使用固定本地续行场景比较任务完成、重复动作与 Token 成本；真实模型调用或不可用外部依赖的验证缺口须明确说明。

## 当前阶段

设计访谈已确认七项用户选择，用户随后确认开始实施。代码、WebUI、命令入口和针对性测试已实现；使用入口和边界见 `docs/local-information-assets.md`，验证结果与既有完整套件失败见 `docs/audits/local-information-assets-verification.md`。
