# WebUI migration implementation record (2026-09-14)

## Scope

The browser control plane now uses a single Vite entry (`web/src/main.tsx`)
and a cc-harness adapter application under `web/src/cc/`. The Python FastAPI
server remains the only Runtime, session store, permission gate, context/memory
authority, and immutable event source. The work deliberately excludes
`D:\agent_learning\外卖`.

## Provenance

The reviewed DeepSeek Harness source was cloned at commit
`c291e7961a515f6d7af9304e7fd1d257929aef26`. Its Web/client source is retained
under [`vendor/deepseek-ui/`](../../vendor/deepseek-ui/) with the upstream
license and third-party notices. The snapshot is a source/provenance boundary;
it is not a second executable frontend or Runtime.

## Runtime integration

- `/api/web/v1` exposes versioned health, bootstrap, capability, settings,
  project, session, approval, stop, resume, timeline, context and SSE routes.
- The aliases delegate to the existing handlers, so REST commands, replayable
  SSE cursors, redaction, approval rejection continuation and project gates
  cannot diverge from legacy `/api` clients.
- `/api/web/v1/capabilities` describes supported controls and explicitly states
  the REST/SSE/cursor contract for the UI.
- `web/src/cc/api.ts` is the only browser transport adapter. It does not write
  Runtime state or store credentials in browser storage.

## Verification

```text
npm run build                         PASS
python -m pytest tests/test_web_facade.py tests/test_webui.py tests/test_web_sse.py -q  PASS
python scripts/build_webui.py        PASS
```

The staged assets in `cc_harness/web_assets/` are generated by
`scripts/build_webui.py`; no Node process is required for an installed Python
package. The application keeps optimistic bubbles only until the matching
immutable event arrives, renders completion envelopes as Runtime evidence
rather than chat prose, and reconnects the run tree through event cursors.

## Known boundary

The upstream DeepSeek monorepo depends on its Cordis/pnpm module graph and is
not compiled as an independent application here. The pinned shell `base.css`
is imported into the existing Vite graph, while the remaining upstream design
tokens and interaction semantics are adapted in cc-harness code. A future
snapshot update must change `SOURCE-COMMIT`, re-run the facade/build tests, and
include a visual review before release.
