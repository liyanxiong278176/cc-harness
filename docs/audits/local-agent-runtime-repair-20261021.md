# 本地 Agent Loop / Context / Memory 修复与复验

日期：2026-10-21。

本次针对 [第一轮真实任务报告](local-agent-trials-20261021.md) 中的失败，先建立确定性复现，再修改产品实现，并保留原始轨迹和修复过程中未通过的试跑。没有删除失败结果或把 runtime 的 completed 标签直接计为通过。

## 原因与修复

| 问题 | 确认的原因 | 修复 |
|---|---|---|
| 未生成产物却完成 | 检查命令被误当作验证；完成契约主要识别 /app 等绝对路径，漏掉本地相对产物；工具批次后直接合成完成 | 排除目录／版本／git 状态检查，拒绝可能掩盖退出码的管道；解析相对输出；产品路径从真实回执重建完成证据 |
| 修复后无法重跑原命令 | 语义幂等键没有区分工作区输入变化，FAILED 也被永久去重 | 本地验证调用绑定工作区变更代次；同一调用重放、在途和未知结果仍保持原键、必须核对 |
| 历史失败导致永久 stalled | 完成门槛把不同 action_id 的历史失败全部视为当前阻塞 | 用 FailureResolved 事件关联成功替代动作／后续验证；保留失败事实，解除已恢复阻塞；不解除未知副作用 |
| 长上下文中反复从头检查 | 动态任务／阶段视图混入只追加历史；ContextProjection.sync 只比较长度，可能漏掉插入的控制消息或错位的观察 | 动态视图单独注入；历史前缀按摘要校验。变化时重建，仅在源索引和摘要均一致时复用 Snip/Prune 表示 |
| 摘要后仍溢出 | 压缩没有预留后续注入的续行、任务和 Skill 视图；旧精确证据片段还能挤占窗口 | 压缩前预留真实控制信息大小；精简模型视图中的历史索引；必要时撤下可回读的旧证据，保留目标、当前状态和原始资料 |
| read_ref 返回下一层引用 | 指针和分页回读结果被再次卸载，形成别名链 | 禁止再次卸载指针／回读；旧链最多跟随八层，每层校验哈希、作用域并检查循环 |
| 卸载阶段整机式卡住 | 在 asyncio 事件循环里同步等待同一个 SQLite 的写锁，锁的释放也依赖该循环 | 写清单移至工作线程；摘要调用有上限并保留原文作为回退。进程栈保存在首轮修复试跑目录 |
| 忘记后 L0 找回旧答案 | 删除 L1 和原会话来源，漏掉跨会话召回结果及改写后的回答 | 记忆撤回时推进历史召回边界，屏蔽撤回前的 L0 回退；原始历史保留；已有已验证 L1 事实仍按原有作用域管理 |
| Skill 正确却不能收尾 | 普通 Read 被内部路径策略拒绝；资源读取方式不明确；验证依赖脚本名称 | 明确 read_skill(resource) 路径；成功的固定资源读取可解决对应旧失败；直接执行的本地 Python 断言脚本支持内容摘要绑定 |
| 产物和校验均正确但持续探索 | 没有独立的完成审查阶段；重复动作被去重后没有解释反馈 | 满足本地门槛后进入无工具的完成审查，模型提交完成或具体缺口，runtime 再核验证据；去重会给出可操作反馈，且修复尝试有上限 |
| 并行工具偶发 SequenceConflict | Worker 与任务控制各用不同的“读序号→提交”锁 | 共用事件构造／提交锁，保留数据库事务、租约 fencing 与跨进程冲突检查 |

对应实现主要位于 `worker.py`、`capability_runtime.py`、`context.py`、`loop_control.py`、`local_verification.py`、`memory/store.py`、`memory/offload/` 与 `execution_control.py`。

## 评测口径与保留证据

- Skill 的无规范对照证明私有知识不可凭空猜测；本次重点核验启用后的实际读取、执行和收尾，不把信息缺失包装为功能成功。

## 实际边界

遗忘采用保守的 L0 边界：撤回后，之前的历史暂不再作为记忆回退来源，避免改写后的旧内容复活；原始历史仍可审计。它可能降低对其他旧会话的回忆覆盖，未来若要求精确到每条派生链，可再细化来源关系。

这些结果是小样本合成任务与确定性契约测试，不是小时级耐久性或所有任务成功的保证。业务语义仍需与项目自己的验收器匹配；本次没有声称整个仓库的全部可选测试都已通过。
