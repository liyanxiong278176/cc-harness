# 长期记忆:AI 怎么"记住"跨会话的东西

> 写给**所有人**——不需要编程背景也能看懂

---

## 一句话总结

> 长期记忆 = **AI 把你告诉它的事情存进"档案库",下次新对话开始时自动翻出来用**。

---

## 为什么需要它?一个真实场景

```
周一(第一次会话):
你: 我住北京,用 VSCode,做 Python 后端
AI: 好的,记下了。
... 聊了很多 ...

周二(全新会话):
你: 帮我优化代码
AI: (完全不知道你住哪、用啥编辑器、做啥)
```

**问题**:AI 没有"档案库",每次新会话都是"失忆状态"。

**解决方案**:让 AI 把重要信息**存起来**,下次开始时**自动加载**。

---

## 一个生活化的类比

把 LLM 想象成一个**很聪明但没有大脑记忆的人**:

- **短期记忆**(context) = 它正在跟你聊的内容,聊完就忘
- **长期记忆**(memory) = 它随身带的小本子,专门记重要的事

每次新对话开始前,它会:
1. 翻开小本子
2. 找到跟当前话题相关的几条
3. 把这几条**抄**到对话开头(作为背景信息)

---

## 记忆存到哪里?

存在电脑本地的一个数据库文件里:

```
~/.cc-harness/memory/<项目文件夹的哈希值>.db
```

**关键点**:
- **本地存储**——不上云,隐私安全
- **按项目隔离**——`D:\agent_learning\cc-harness` 项目的记忆,不会污染 `D:\other-project` 项目
- **向量数据库**(SQLite + sqlite-vec)——不是普通文本,后面解释

---

## 怎么存?(4 步流程)

当你说"记住我住北京"或系统判断该保存时,会发生这 4 步:

```
你说: "我住北京"
    │
    ↓
[1] 把"我住北京"转成数字(向量)
    │
    │   "我住北京" → [0.12, -0.34, 0.78, ..., 0.05]
    │   (一串数字,类似"指纹",语义相似的文字指纹也相似)
    │
    ↓
[2] 在档案库里搜:有没有"指纹"相似的已有记忆?
    │
    │   找到一条: "用户住上海"(指纹和"我住北京"很相似)
    │
    ↓
[3] 让 AI 决定怎么处理这条记忆
    │
    │   AI 看到老的是"上海"、新的是"北京" → 矛盾 → UPDATE(更新成北京)
    │
    ↓
[4] 把决定写进档案库
    │
    └─→ "用户住北京" 入库(覆盖之前的"上海")
```

---

## 两种触发方式

### 1. LLM 主动调(显式)

AI 自己判断"这条值得记",调用 `memory_save` 工具:

```
AI 在内部想:"用户说他住北京,这是重要的个人信息,应该记下来。"
AI 调用工具:memory_save("用户住北京")
```

### 2. 系统自动提取(隐式)

当对话**接近装满脑子时**(占用 > 55%),系统自动跑 Pipeline:

```
对话占用 60% → 系统自动扫描最近对话 → 提取重要信息 → 存进档案库
```

**为什么要自动?** 你聊着聊着不会主动说"记住这条",但事后又需要。自动提取帮你兜底。

---

## 怎么"读"?(检索流程)

每次 AI 要回答你之前,会先**翻档案库**:

```
[开始新对话]
    ↓
[1] 你说:"帮我推荐餐厅"
    ↓
[2] 系统把你的话转成数字(指纹)
    │
    "帮我推荐餐厅" → [0.45, -0.12, ...]
    │
    ↓
[3] 在档案库找"指纹"最像的前 3 条
    │
    找到:
      - "用户住北京"(指纹相似度 0.72)
      - "用户喜欢川菜"(相似度 0.65)
      - "用户周末常在家做饭"(相似度 0.58)
    │
    ↓
[4] 把这 3 条作为背景信息,塞到对话开头
    │
    "系统提示:关于这个用户,我们记得:
      - 用户住北京
      - 用户喜欢川菜
      - 用户周末常在家做饭"
    │
    ↓
[5] AI 基于这些"已知信息"回答
    │
    "考虑到您住北京、喜欢川菜,推荐这几家..."
```

## 关键特性

### ✅ 结构化记忆

cc-harness 的记忆是**单条事实**,每条有 ADD/UPDATE/DELETE/NOOP 4 种操作:

```
"我住上海"  → ADD(新增一条)
"我住北京"  → UPDATE(更新之前的上海)
"忘了那条关于 X 的" → DELETE(删除)
"我住北京"  → NOOP(已经有了,啥也不做)
```

**对比**:Claude Code 的 CLAUDE.md 是**一整篇文档**,无法去重 / 精确更新。

### ✅ 跨项目隔离

```
D:\agent_learning\cc-harness\   → memory/项目A.db
D:\other-project\                → memory/项目B.db
```

切换目录后,记忆自动换。

### ✅ 不被压缩干掉

长期记忆块**专门标记**了 `_memory_block=True`,在上下文压缩的 4-tier 里**完全冻结**:

```
压缩时:
  普通消息 → 可以剪短 / 替换 / 摘要
  记忆块   → 永远不动(重要信息不丢)
```

---

## 怎么查看 / 管理?

cc-harness 提供 4 个 slash 命令:

```
/memories list     → 列出所有记忆(看看 AI 记住了啥)
/memories count    → 总共有几条
/memories forget <id>  → 删除某条(它记错了)
/memories clear    → 清空全部
```

---

## 怎么关闭?

如果你不想用这个功能,在 `.env` 里:

```bash
# 关掉长期记忆
MEMORY_ENABLED=false

# 或者不设 EMBEDDING_* 变量(因为需要 embedding API 才能跑)
```

## 4 步流程图(完整版)

```
              ┌─ 主动:LLM 调 memory_save
              │
触发 ─────────┤
              │
              └─ 自动:对话占用 > 55% 时 Pipeline 启动

[1] Embedding     "用户住北京" → 向量(指纹)
       │
       ↓
[2] KNN 搜索       找指纹最像的几条已有记忆
       │
       ↓
[3] LLM 决策       ADD / UPDATE / DELETE / NOOP
       │
       ↓
[4] 写库            SQLite + sqlite-vec

读取时:
       ↓
[1] 当前对话内容 → 向量
       ↓
[2] KNN 搜索 → top-k 相关记忆
       ↓
[3] 格式化成背景块,塞到 system prompt
       ↓
[4] LLM 基于这些"已知"回答
```

## 一张图对比"两种 AI 助手"

| | 一次性会话(没记忆) | cc-harness(有长期记忆) |
|---|---|---|
| **新会话开始** | 啥都不知道 | 自动加载相关历史 |
| **重复信息** | 用户每次重新说 | 自动去重 |
| **更新信息** | 用户手动修正 | 自动 UPDATE |
| **跨项目** | 不分项目 | 按 cwd 隔离 |
| **依赖** | 无 | 需要 embedding API |
| **代价** | 0 | 检索时 1 次 embedding 调用 |

## 看不下去的可以只看这 3 行

1. **为什么需要**:AI 不记忆,新会话就失忆——长期记忆解决这个
2. **怎么存**:对话触发 → 转数字(指纹) → 搜相似的 → AI 决定增/改/删 → 写库
3. **怎么用**:每次新对话开始,自动从档案库找相关的 3-5 条塞到对话开头

## 与上下文压缩的关系

```
┌────────────────────────────────────────────┐
│  长期记忆(本文件)                          │
│  跨 session,持久化,自动检索                │
│  → 解决"明天就忘"                          │
└────────────────────────────────────────────┘
                    ↓ 检索结果注入
┌────────────────────────────────────────────┐
│  上下文压缩(另一个文件)                    │
│  单 session 内,自动,4-tier                │
│  → 解决"今天聊太久装不下"                  │
└────────────────────────────────────────────┘
```

两者**配合**:长期记忆保证跨 session 不断片,短期压缩保证单 session 不爆 context。**记忆块在压缩中被冻结**,所以重要信息不会因为压缩丢失。
