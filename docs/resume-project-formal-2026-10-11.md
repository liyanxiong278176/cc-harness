# 长链路编程 Agent 运行框架（cc-harness）

**项目背景：** 面向长链路编程任务开发 Agent Runtime，围绕任务中断恢复、上下文压缩、跨会话记忆和工具调用安全控制，处理执行状态丢失、上下文膨胀及历史信息遗忘等问题；在内部构造场景中验证文件读取、代码修改、测试执行及异常退出后的状态恢复。

- **任务执行与恢复：** 设计基于 Run 状态机、持久化事件与 Checkpoint 的恢复机制，记录模型调用、工具动作及执行结果，结合 Worker 租约与过期提交隔离控制并发执行；覆盖动作准备、外部效果完成但结果尚未提交等 10 类中断边界，200 次进程异常退出后已提交状态恢复 200/200，状态加载中位耗时 11.9 ms，20 次过期租约下旧 Worker 提交均被拒绝。
- **上下文管理：** 实现 Snip、Prune、Summary 三级压缩，保留系统指令、Run 状态、近期对话及带来源的任务证据，通过内容寻址存储保留原文并支持回查；修复摘要重建丢失工具调用配对及压缩后重新读取受执行去重阻塞的问题。在 100 个内部双模块编程任务、600 次对照执行中，相比关闭压缩，API 返回的总 Token 用量降低 24.2%（包含 96 次摘要调用），任务通过率由 91.3% 变为 92.3%，保持基本不变。
- **长期记忆：** 构建 L1 事实、L2 场景、L3 用户画像分层架构及 L3→L2→L1 渐进检索链路，通过 SQLite、向量检索与全文检索管理跨会话信息。在 100 段构造历史、400 条查询的三组对照中，每组重复 3 次；相较仅提供近期历史，模型回答准确率由 16.5% 提升至 42.0%（+25.5 个百分点），输入 Token 减少 57.3%。
- **工具调用安全：** 针对 Prompt Injection、工具越权与敏感信息泄露，实现非可信内容来源校验、指令与数据隔离、ALLOW／ASK／DENY 权限决策及输出 DLP。在 300 个攻击、300 个正常组件用例中，100 个攻击型权限输入有 70 个硬拒绝、30 个转人工确认；120 个原文密钥格式样例中 108 个完成脱敏，200 个正常 DLP 文本均未被改写。

**数据口径：** 全部指标来自内部构造场景，不代表线上业务收益。上下文结果来自 V12 完整回归对照：100 题、每条件三次，模型及执行预算一致；使用实验压力阈值，未验证默认生产阈值。总 Token 包含摘要输入与输出；1 次超时请求未返回用量，自动重试成功，其未知用量未计入；按该相同请求的输入及输出上限保守补计，降幅仍约 24.0%。三次重复不是 300 个独立任务，通过率差的任务聚合 Bootstrap 95% 区间为 [-1.0, +3.0] 个百分点，不能据此宣称普遍提升。记忆完整历史对照为 100%，分层为 42%；不能声称优于完整历史。状态加载不是完整任务恢复耗时，权限 ASK 不是自动拒绝或放行，安全组件评测不是完整 Agent 攻击成功率。

上下文证据与完整失败分布见 [V12 对照报告](eval/context-quality-2026-10-11.md)；其他指标及早期压缩失败见 [原扩测报告](eval/resume-formal-2026-10-11.md)。面试时应优先说明适用范围和已发现的问题。
