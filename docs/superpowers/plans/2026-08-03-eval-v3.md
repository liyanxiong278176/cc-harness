# Eval v3 Implementation Plan

## Implementation status

- Phase 1 evidence foundation: implemented and verified on 2026-08-03.
- Phase 2 durable local runner foundation: implemented and verified on 2026-08-03. Framework
  adapters, deterministic grader caches and CI sharding remain later integration work.
- Phase 3 internal gate foundation: implemented and verified on 2026-08-03. The nine-domain native
  catalog, deterministic pytest adapter, veto decisions, paired comparison and decision reports are
  ready; activation in L1/L2 workflows remains integration work.
- Phase 4 migration foundation: implemented and verified on 2026-08-04. Promptfoo and LoCoMo now
  import strict, content-addressed evidence into frozen multi-domain Task Contracts; live parity
  runs and dual-human calibration annotation remain evidence-collection work.
- Phase 5 external capability and parity foundation: implemented and offline-verified on
  2026-08-04. Live public-benchmark runs and cross-harness `deepseek-v4-flash` evidence remain
  evidence-collection work; Phase 6 has not started.

## Phase 1: Evidence foundation

- Add immutable Pydantic models for Task Contract, Eval Run Manifest and Trial Result.
- Add shared status, tier, state-profile, grader and nine-domain enums.
- Add content-addressed artifact references, canonical JSON and SHA-256 fingerprints.
- Add an adapter protocol and typed trial request.
- Lock contracts with focused unit tests and an ADR.

Exit: records round-trip deterministically, reject malformed evidence and have no dependency on a
specific evaluation framework.

## Phase 2: Reliable execution

- Persist run, trial and attempt state before dispatch.
- Execute each trial in a disposable workspace with explicit timeout, cancellation and network
  policy.
- Make subprocess and adapter failure fail closed; distinguish product failure from invalid trial.
- Persist heartbeats, retry lineage, logs and artifact hashes for resume.
- Add local sharding and deterministic fixture caches; do not cache model trials by default.

Exit: a killed runner can resume without losing, duplicating or silently passing a trial.

## Phase 3: Internal release gates

- Convert critical coding, native tool, context, memory, recovery, safety and TUI behaviors to
  versioned Task Contracts.
- Add deterministic state and outcome graders.
- Implement veto evaluation, frozen splits, paired comparisons and inconclusive handling.
- Produce a machine-readable release decision and rebuildable Markdown report.

Exit: L1/L2 gates can block regressions with traceable objective evidence.

## Phase 4: Existing evaluator migration

- Wrap Promptfoo execution and preserve raw Promptfoo output as artifacts.
- Replace placeholder calibration labels through dual human annotation and adjudication.
- Wrap LoCoMo, repair the unified return path and expand dataset/task coverage.
- Replace approximate token counting with provider or tokenizer-backed counts.
- Re-enable red-team workflows at the appropriate tier.

Exit: current strengths appear in the unified nine-domain report without losing specialized views.

Implementation notes (2026-08-04):

- `PromptfooEvidenceAdapter` and `LocomoEvidenceAdapter` reject malformed or incomplete framework
  output and preserve raw JSON, reports, metrics and trajectories in the object store.
- Frozen Promptfoo and LoCoMo Task Contracts connect specialized results to six capability domains;
  release veto semantics remain owned by the evidence core.
- Promptfoo subprocess failures propagate, and LoCoMo writes a real metrics JSON consumed by the
  unified report path.
- Offline LoCoMo tests cannot invoke Deepeval GEval without explicit opt-in. Context chunk token
  counts use the project tokenizer instead of word-count approximations.
- The 50 placeholder calibration records are now unverified `candidates`, not a gold `baseline`.
  Promotion requires two independent annotations and a separate adjudicator.
- A bounded `deepseek-v4-flash` Promptfoo subset runs at L3 weekly cadence and preserves raw CI
  artifacts. The full local suite remains intentionally outside PR latency budgets.

Remaining exit evidence:

- Complete dual-human annotation and adjudication for a representative calibration baseline.
- Run live Promptfoo and full LoCoMo imports through the durable runner and compare specialized
  reports against normalized Trial Results before treating migration parity as closed.

## Phase 5: External capability and parity

- Add Harbor/Terminal-Bench and SWE-bench Verified subset adapters.
- Add Claude Code and cc-harness launch adapters with identical Task Contract semantics.
- Pin `deepseek-v4-flash` for same-model harness comparisons and record resolved model versions.
- Add risk-stratified adaptive paired sampling and harness-component ablations.

Exit: comparison claims include uncertainty, invalid-run accounting, cost/latency and exact evidence.

Implementation notes (2026-08-04):

- Frozen launch profiles build shell-free argv for cc-harness and Claude Code, pass prompts
  over stdin, expose only allowlisted environment variables and bound stdout/stderr capture.
- Both parity profiles pin `deepseek-v4-flash`. Structured output must report the resolved model;
  missing, conflicting or different model evidence is invalid for parity. Claude Code accepts an
  explicit gateway settings file and never silently falls back to its default model.
- `cc-harness --output-format json` records the provider-reported model, API tokens, model calls and
  tool calls. Raw launch output remains available to the caller for content-addressed persistence.
- Harbor imports its native TrialResult schema, including verifier rewards, exceptions, timings,
  tokens and cost. SWE-bench imports exactly one official prediction and keyed evaluation report.
  Both preserve raw framework artifacts and reject unknown, duplicate or mismatched evidence.
- Parity validation rejects drift in comparison group, task set, budget, seed, repetitions, split,
  environment, requested model or resolved model. Risk-stratified adaptive sampling, paired Wilson
  decisions, invalid limits, usage summaries and single-component ablation contracts are available.

Remaining exit evidence:

- The local Anthropic Messages-compatible Claude Code route was updated and model-identity
  preflight passed on 2026-08-04. Both cc-harness and Claude Code reported resolved model
  `deepseek-v4-flash` with valid structured evidence. This closes route identity only; it is not
  benchmark-performance evidence.
- Launch cost is nullable rather than treating missing provider cost as zero. Claude Code reported
  cost in preflight, while cc-harness currently reports tokens but no provider cost; cost claims
  therefore require a versioned price schedule or provider cost telemetry.
- A 10-pair same-model canary completed on 2026-08-04: cc-harness passed 9/10 and Claude Code 10/10,
  with nine ties and one Claude Code win. The paired result is inconclusive because there was only
  one discordant pair. Seven additional provider/budget-invalid attempts were preserved and
  excluded from outcomes.
- The single cc-harness loss exposed LF exact-edit arguments failing against a CRLF file. Edit now
  normalizes arguments to the target newline style while retaining hash, ambiguity and atomic-write
  safeguards; a targeted post-fix live rerun passed. JSON print output also bypasses the Windows GBK
  encoding boundary with explicit UTF-8 bytes.
- Detailed metrics, limitations and evidence roots are recorded in
  `docs/eval/2026-08-04-cc-vs-claude-canary.md`.
- The ad hoc canary is now frozen as ten versioned Task Contracts in `eval.canary`. Fixture ZIPs,
  instructions, protected-test hashes, launch streams, grader output and final implementations are
  content addressed through `EvalStore`. The CRLF regression remains a first-class catalog task.
- `HarnessCanaryAdapter` normalizes live cc-harness and Claude Code runs into Trial Results without
  converting missing provider cost to zero. Usage summaries publish a total cost only when all
  selected trials report cost.
- `PairedCanaryRunner` preserves all invalid attempts and synchronizes both harnesses when a 429,
  transient 5xx, overload or provider retry-budget failure occurs. Functional failures and
  non-transient invalid evidence are not retried. Adaptive trials may be appended while a run is
  active, while completed runs remain immutable.
- Three advanced same-model tasks now cover cross-file runtime configuration, checkpoint recovery
  and conflicting decision records. The first run produced one tie, one Claude Code win and one
  invalid pair, so it remains inconclusive. Both Claude checkpoint attempts exceeded the launch
  budget and remain preserved as invalid evidence.
- The decision-record loss exposed a five-iteration production default that discarded a pending
  write before execution. Pending tools from the final allowed model call now execute before the
  loop stops. The runtime also accepts a bounded iteration budget from the CLI and the eval launcher
  passes the Task Contract's model-call budget. A targeted post-fix run executed the write on
  iteration six and both harnesses passed; the original comparison was not rewritten.
- Claude stream telemetry now counts unique assistant `tool_use` blocks. Earlier immutable reports
  retain their original zero values; replaying the post-fix raw stream with the corrected parser
  reports 11 tool calls. Detailed evidence and limitations are in
  `docs/eval/2026-08-04-advanced-cc-vs-claude-canary.md`.
- The shared runtime now has explicit, idempotent shutdown ownership for the main and judge LLMs,
  MCP, memory clients and store, L2 client, session store and session executor. Partial memory-stack
  initialization closes resources already created, and one shutdown failure does not prevent the
  remaining resources from closing.
- Agent and context-summary async streams are explicitly closed when iteration exits early. The MCP
  HTTP transport uses the current `streamable_http_client` API, and pytest uses function-scoped
  async fixture loops. A 77-test lifecycle regression passed with deprecation, runtime,
  unhandled-thread and unraisable warnings promoted to errors. A separate 163-test agent, context,
  memory, reflection and drift regression passed with async runtime warnings promoted to errors.
- Run a risk-stratified Harbor/Terminal-Bench and SWE-bench Verified subset in isolated workers,
  preserve raw trajectories/patches/logs and publish paired uncertainty, invalids, latency and cost.
- Execute component ablations against the same frozen tasks and budgets before attributing any
  observed gain to context, memory, tool or agent-loop changes.

## Phase 6: Governance and scale

- Add redacted production-failure intake and human-confirmed regression promotion.
- Implement holdout rotation, retirement and exposure audit.
- Add expiring low-risk gate exceptions; forbid exceptions for critical vetoes.
- Generate L4 content-addressed Release Evaluation Evidence Bundles.
- Introduce CI shards, then remote workers only after measured queue or isolation bottlenecks.

Exit: release decisions are auditable, reproducible and operationally sustainable.
